## 🗄️ مرحله ۲: افزودن پایگاه‌داده PostgreSQL

### ۲.۱ ساخت سرویس دیتابیس

1. در پروژه Railway خود، روی **New** کلیک کنید
2. گزینه **Database** را انتخاب کنید
3. **PostgreSQL** را انتخاب کنید

Railway به‌صورت خودکار یک پایگاه‌داده PostgreSQL برای شما می‌سازد.

### ۲.۲ بررسی اتصال

بعد از چند ثانیه:

1. روی سرویس PostgreSQL کلیک کنید
2. به تب **Variables** بروید
3. مقدار `DATABASE_URL` را ببینید - این آدرس اتصال دیتابیس شماست

> **خودکارسازی:** برنامه به‌صورت خودکار این متغیر را تشخیص می‌دهد. نیازی به کپی کردن دستی نیست!

## ⚙️ مرحله ۳: تنظیم متغیرهای ضروری

به سرویس اصلی برنامه (Web Service) بروید و متغیرهای زیر را اضافه کنید:

### ۳.۱ متغیرهای اجباری

| متغیر | مقدار | توضیح |
|-------|-------|-------|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | ارجاع خودکار به دیتابیس |
| `APP_SECRET` | یک رشته تصادفی طولانی | برای امنیت توکن‌ها |
| `APP_URL` | `https://your-app.up.railway.app` | آدرس عمومی برنامه |

### نحوه تولید APP_SECRET

```bash
# در ترمینال محلی اجرا کنید
openssl rand -hex 32
```

یا از یک تولیدکننده رمز عبور آنلاین استفاده کنید.

### ۳.۲ نحوه افزودن متغیرها در Railway

1. به سرویس Web بروید
2. روی تب **Variables** کلیک کنید
3. روی **New Variable** کلیک کنید
4. نام و مقدار هر متغیر را وارد کنید
5. **Add** را بزنید

> **نکته مهم:** برای `DATABASE_URL` دقیقاً از همین عبارت استفاده کنید:
> ```
> ${{Postgres.DATABASE_URL}}
> ```
> Railway به‌صورت خودکار این را به آدرس واقعی دیتابیس تبدیل می‌کند.

## 🔧 مرحله ۴: پیکربندی Volume (برای ذخیره‌سازی فایل)

اگر از فضای ابری S3 استفاده نمی‌کنید، باید یک Volume اضافه کنید:

### ۴.۱ افزودن Volume

1. به سرویس Web بروید
2. روی تب **Volumes** کلیک کنید
3. روی **New Volume** کلیک کنید
4. مسیر Mount را `/app/storage` قرار دهید
5. حجم پیشنهادی: 1GB (قابل تغییر بعدی)

### ۴.۲ تنظیم متغیر STORAGE_DIR

در تب Variables:

```
STORAGE_DIR=/app/storage
```

> ⚠️ **هشدار:** اگر Volume اضافه نکنید، فایل‌های آپلودشده با هر بار استقرار پاک می‌شوند.

## 🌐 مرحله ۷: دامنه اختصاصی (اختیاری)

### ۷.۱ افزودن دامنه در Railway

1. به سرویس Web بروید
2. تب **Settings** → **Domains**
3. روی **Add Custom Domain** کلیک کنید
4. دامنه خود را وارد کنید (مثلاً `shop.example.com`)

### ۷.۲ تنظیم DNS

در پنل مدیریت دامنه خود:

**برای دامنه اصلی:**
```
Type: A
Name: @
Value: <IP ارائه‌شده توسط Railway>
```

**برای زیردامنه:**
```
Type: CNAME
Name: shop
Value: <domain>.up.railway.app
```

### ۷.۳ به‌روزرسانی APP_URL

1. در Railway، متغیر `APP_URL` را به‌روز کنید:
   ```
   APP_URL=https://shop.example.com
   ```
2. برنامه به‌صورت خودکار ری‌استارت می‌شود

### ۷.۴ ثبت مجدد Webhook تلگرام

1. وارد پنل مدیریت شوید
2. به بخش تنظیمات ربات بروید
3. روی **Register Webhook** کلیک کنید

### بازیابی از پشتیبان

```bash
# دانلود پشتیبان از S3

# بازیابی در دیتابیس
gunzip -c backup.sql.gz | psql "$DATABASE_URL"
```

یا از طریق پنل مدیریت اقدام کنید.

## 🛠️ عیب‌یابی مشکلات رایج

### مشکل: "DATABASE_URL is not set"

**علت:** متغیر DATABASE_URL تنظیم نشده است.

**راه‌حل:**
1. به تب Variables بروید
2. متغیر را اضافه کنید:
   ```
   DATABASE_URL=${{Postgres.DATABASE_URL}}
   ```
3. مطمئن شوید سرویس PostgreSQL وجود دارد

### مشکل: صفحه سفید یا خطای 500

**علت:** معمولاً دیتابیس در دسترس نیست یا مایگریشن شکست خورده است.

**راه‌حل:**
1. بررسی کنید سرویس PostgreSQL روشن است
2. لاگ‌های Railway را ببینید
3. متغیر DATABASE_URL را بررسی کنید

### مشکل: ربات تلگرام پاسخ نمی‌دهد

**علت:** Webhook ثبت نشده یا توکن اشتباه است.

**راه‌حل:**
1. توکن ربات را در پنل مدیریت بررسی کنید
2. روی **Register Webhook** کلیک کنید
3. مطمئن شوید `APP_URL` درست است
4. در تلگرام `/start` بفرستید

### مشکل: فایل‌های آپلودشده پاک می‌شوند

**علت:** Volume اضافه نکرده‌اید یا از S3 استفاده نمی‌کنید.

**راه‌حل:**
1. یک Volume به سرویس اضافه کنید
2. یا S3 پیکربندی کنید
3. متغیر `STORAGE_DIR=/app/storage` را تنظیم کنید

### مشکل: پرداخت TON تأیید نمی‌شود

**علت:** تنظیمات TON ناقص است.

**راه‌حل:**
1. `TON_PROVIDER` را تنظیم کنید (toncenter یا tonapi)
2. `TON_API_KEY` را وارد کنید
3. آدرس کیف پول را بررسی کنید
4. مطمئن شوید `PAYMENT_DEV_MODE=false` است

### مشکل: Health check fails

**علت:** سرویس بالا آمده اما دیتابیس یا storage در دسترس نیست.

**راه‌حل:**
1. به `/health` بروید
2. بخش `checks` را ببینید
3. مشکل مشخص‌شده را رفع کنید

## 📊 مقیاس‌دهی (برای ترافیک بالا)

### جداسازی Worker

برای عملکرد بهتر:

1. در سرویس Web:
   ```
   ENABLE_INLINE_WORKER=false
   ```

2. یک سرویس جدید از همان مخزن بسازید

3. در سرویس جدید:
   - Start Command: `node dist/src/worker.js`
   - سایر متغیرها مانند سرویس Web

4. حالا:
   - سرویس Web فقط درخواست‌ها را پردازش می‌کند
   - سرویس Worker کارهای پس‌زمینه را انجام می‌دهد
