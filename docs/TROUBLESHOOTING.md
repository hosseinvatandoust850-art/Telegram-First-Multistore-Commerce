## 🔍 روش کلی عیب‌یابی

### ۱. بررسی لاگ‌ها

1. به سرویس Web بروید
2. تب **Deployments** → **View Logs**
3. خطاهای اخیر را ببینید

به آدرس زیر بروید:

```
https://your-app.up.railway.app/health
```

وضعیت هر بخش را ببینید:

- ✅ Database
- ✅ Storage
- ✅ Worker

### ۳. بررسی متغیرها

در Railway:

1. به سرویس Web بروید

## ❌ مشکلات استقرار (Deployment)

### مشکل: Build شکست می‌خورد

**پیام خطا:** `Build failed` یا `Docker build error`

#### علل احتمالی:

1. فایل‌های پروژه ناقص هستند
2. وابستگی‌ها نصب نمی‌شوند
3. کامپایل TypeScript شکست می‌خورد

#### راه‌حل:

1. **بررسی لاگ Build:**
   - در Railway، به تب Deployments بروید
   - روی آخرین deployment کلیک کنید
   - لاگ را بخوانید

2. **بررسی package.json:**
   ```bash
   # محلی اجرا کنید
   npm install
   npm run build
   ```

3. **بررسی نسخه Node:**
   - مطمئن شوید Node.js >= 20 است
   - در Railway از image درست استفاده کنید

4. **Push مجدد:**
   ```bash
   git add .
   git commit -m "fix: dependency issues"
   git push
   ```

---

### مشکل: Migration شکست می‌خورد

**پیام خطا:** `Migration failed` یا `Database error`

#### علل احتمالی:

1. دیتابیس در دسترس نیست
2. DATABASE_URL اشتباه است
3. مایگریشن تکراری اجرا شده است

#### راه‌حل:

1. **بررسی اتصال دیتابیس:**
   ```bash
   # در Railway Variables بررسی کنید
   DATABASE_URL=${{Postgres.DATABASE_URL}}
   ```

2. **بررسی وضعیت PostgreSQL:**
   - در Railway، سرویس Postgres را ببینید
   - مطمئن شوید Running است
   - اگر Stopped است، Start کنید

3. **بررسی مایگریشن‌های قبلی:**
   ```sql
   SELECT * FROM _migrations ORDER BY version DESC;
   ```

4. **اجرای دستی مایگریشن (فقط در صورت نیاز):**
   ```bash
   # در Railway Shell
   node dist/scripts/migrate.js
   ```

---

### مشکل: برنامه شروع نمی‌شود

**پیام خطا:** `Exited with code 1` یا `CrashLoopBackOff`

#### علل احتمالی:

1. متغیرهای محیطی ناقص
2. پورت در دسترس نیست
3. خطا در کد برنامه

#### راه‌حل:

1. **بررسی متغیرهای ضروری:**
   - `DATABASE_URL` ✅
   - `APP_SECRET` ✅
   - `PORT` ✅ (باید 8080 باشد)

2. **بررسی لاگ Startup:**
   ```
   Starting server on port 8080...
   Database connected successfully
   Migrations completed
   Server listening on http://0.0.0.0:8080
   ```

3. **تست محلی:**
   ```bash
   npm run dev
   # باید بدون خطا اجرا شود
   ```

## 🗄️ مشکلات دیتابیس

### مشکل: "DATABASE_URL is not set"

**پیام خطا:** `Missing required configuration: DATABASE_URL`

#### راه‌حل:

1. در Railway Variables:
   ```
   DATABASE_URL=${{Postgres.DATABASE_URL}}
   ```

2. مطمئن شوید سرویس PostgreSQL وجود دارد

3. برنامه را ری‌استارت کنید

---

### مشکل: اتصال به دیتابیس برقرار نمی‌شود

**پیام خطا:** `Connection refused` یا `ETIMEDOUT`

#### علل احتمالی:

1. دیتابیس خاموش است
2. URL اشتباه است
3. محدودیت اتصال (pool full)

#### راه‌حل:

1. **بررسی وضعیت دیتابیس:**
   - در Railway، سرویس Postgres را ببینید
   - اگر Stopped است، Start کنید

2. **بررسی DATABASE_URL:**
   ```
   # باید شبیه این باشد:
   postgresql://postgres:password@host:5432/dbname
   ```

3. **بررسی Pool:**
   ```
   DATABASE_POOL_MAX=10
   ```

4. **ری‌استارت سرویس:**
   - در Railway، روی Restart کلیک کنید

---

### مشکل: جدول وجود ندارد

**پیام خطا:** `relation "Store" does not exist`

#### راه‌حل:

1. **اجرای مایگریشن:**
   ```bash
   node dist/scripts/migrate.js
   ```

2. **بررسی جداول:**
   ```sql
   \dt
   -- باید لیست جداول را ببینید
   ```

3. **اگر مایگریشن شکست خورده:**
   - لاگ مایگریشن را ببینید
   - مشکل را رفع کنید
   - دوباره اجرا کنید

## 🤖 مشکلات تلگرام

### مشکل: ربات پاسخ نمی‌دهد

**علت:** Webhook ثبت نشده یا توکن اشتباه است.

#### راه‌حل:

1. **بررسی توکن:**
   - در پنل مدیریت، توکن را بررسی کنید
   - با @BotFather چک کنید

2. **ثبت Webhook:**
   - در پنل مدیریت، روی **Register Webhook** کلیک کنید
   - پیام موفقیت را ببینید

3. **تست ربات:**
   ```
   در تلگرام: /start
   باید پاسخ دریافت کنید
   ```

4. **بررسی لاگ:**
   ```
   Telegram webhook received for store XYZ
   Bot response sent successfully
   ```

---

### مشکل: Webhook ثبت نمی‌شود

**پیام خطا:** `Webhook registration failed` یا `Invalid URL`

#### علل احتمالی:

1. URL HTTPS نیست
2. دامنه در دسترس نیست
3. SSL certificate مشکل دارد

#### راه‌حل:

1. **بررسی APP_URL:**
   ```
   APP_URL=https://your-app.up.railway.app
   # باید https باشد
   ```

2. **تست URL:**
   ```bash
   curl https://your-app.up.railway.app/health
   # باید 200 برگرداند
   ```

3. **اگر دامنه اختصاصی دارید:**
   - مطمئن شوید DNS تنظیم است
   - منتظر SSL بمانید (ممکن است چند دقیقه طول بکشد)

4. **ثبت مجدد:**
   - در پنل مدیریت، دوباره Register Webhook را بزنید

---

### مشکل: توکن نامعتبر است

**پیام خطا:** `Invalid bot token` یا `Unauthorized`

#### راه‌حل:

1. **دریافت توکن جدید:**
   - در تلگرام: @BotFather
   - دستور: `/revoke`
   - ربات خود را انتخاب کنید
   - توکن جدید بگیرید

2. **به‌روزرسانی توکن:**
   - در پنل مدیریت، توکن جدید را وارد کنید
   - ذخیره کنید

3. **تست:**
   - در تلگرام `/start` بفرستید

---

## 💰 مشکلات پرداخت

### مشکل: پرداخت TON تأیید نمی‌شود

**علت:** تنظیمات TON ناقص است یا API در دسترس نیست.

#### راه‌حل:

1. **بررسی تنظیمات:**
   ```
   TON_PROVIDER=toncenter
   TON_API_KEY=<your-key>
   TON_PAYMENT_ADDRESS=<wallet-address>
   ```

2. **بررسی API Key:**
   - به سایت toncenter.com بروید
   - API key خود را بررسی کنید
   - اگر منقضی شده، جدید بگیرید

3. **بررسی آدرس کیف پول:**
   - باید آدرس معتبر TON باشد
   - با شبکه mainnet/testnet مطابقت داشته باشد

4. **بررسی لاگ:**
   ```
   Polling TON payments...
   Payment found for invoice XYZ
   Order marked as PAID
   ```

### مشکل: پرداخت دستی آپلود نمی‌شود

**علت:** فضای ذخیره‌سازی مشکل دارد.

#### راه‌حل:

1. **بررسی Storage:**
   - به `/health` بروید
   - وضعیت storage را ببینید

2. **اگر Local است:**
   - Volume اضافه کنید
   - `STORAGE_DIR=/app/storage`

3. **اگر S3 است:**
   - کلیدها را بررسی کنید
   - دسترسی باکت را چک کنید

4. **تست آپلود:**
   - یک محصول با تصویر اضافه کنید
   - باید بدون خطا آپلود شود

## 📁 مشکلات ذخیره‌سازی

### مشکل: فایل‌های آپلودشده پاک می‌شوند

**علت:** Volume یا S3 پیکربندی نشده است.

#### راه‌حل:

1. **اضافه کردن Volume:**
   - در Railway → Volumes → New Volume
   - مسیر: `/app/storage`
   - حجم: حداقل 1GB

2. **تنظیم متغیر:**
   ```
   STORAGE_DIR=/app/storage
   ```

3. **یا پیکربندی S3:**
   ```
   S3_ENDPOINT=...
   S3_BUCKET=...
   S3_ACCESS_KEY_ID=...
   S3_SECRET_ACCESS_KEY=...
   ```

4. **تست:**
   - یک محصول با تصویر اضافه کنید
   - برنامه را ری‌استارت کنید
   - تصویر باید باقی بماند

---

### مشکل: آپلود فایل شکست می‌خورد

**پیام خطا:** `Upload failed` یا `Storage not writable`

#### راه‌حل:

1. **بررسی مجوزها:**
   ```bash
   # در Railway Shell
   ls -la /app/storage
   # باید writable باشد
   ```

2. **بررسی حجم:**
   - حجم Volume را چک کنید
   - اگر پر است، افزایش دهید

3. **بررسی S3:**
   - دسترسی باکت را بررسی کنید
   - CORS settings را چک کنید

4. **بررسی اندازه فایل:**
   ```
   MAX_UPLOAD_BYTES=26214400
   # پیش‌فرض 25MB است
   ```

4. **بررسی لاگ:**
   - ببینید build موفق بوده است
   - migrations اجرا شده‌اند

1. **اضافه کردن Volume:**
   - قبل از به‌روزرسانی بعدی
   - مسیر: `/app/storage`

2. **یا استفاده از S3:**

   - همیشه از S3 استفاده کنید

## ⚡ مشکلات عملکرد

### مشکل: برنامه کند است

**علت:** منابع کم یا ترافیک بالا.

#### راه‌حل:

1. **بررسی منابع:**
   - در Railway، Metrics را ببینید
   - CPU و RAM را چک کنید

2. **افزایش منابع:**
   - در Railway، Plan را ارتقا دهید
   - یا Instance را بزرگ‌تر کنید

3. **جداسازی Worker:**
   ```
   ENABLE_INLINE_WORKER=false
   ```
   - یک سرویس جدا برای worker بسازید

4. **بهینه‌سازی دیتابیس:**
   - ایندکس‌ها را بررسی کنید
   - queryهای سنگین را بهینه کنید

---

### مشکل: Time-out رخ می‌دهد

**علت:** عملیات طولانی‌مدت در حال اجرا است.

#### راه‌حل:

1. **بررسی Cron Jobs:**
   - BACKUP_CRON را بررسی کنید
   - TON_POLL_INTERVAL را چک کنید

2. **افزایش Timeout:**
   ```
   healthcheckTimeout = 300
   ```

3. **بهینه‌سازی کد:**
   - عملیات طولانی را به worker منتقل کنید
   - از queue استفاده کنید

## 🔐 مشکلات امنیتی

### مشکل: دسترسی غیرمجاز

**علت:** JWT یا Session مشکل دارد.

#### راه‌حل:

1. **بررسی APP_SECRET:**
   - باید رشته تصادفی طولانی باشد
   - در همه سرویس‌ها یکسان باشد

2. **Clear Sessions:**
   - کاربران را logout کنید
   - دوباره login کنند

3. **بررسی لاگ:**
   ```
   Invalid token for user XYZ
   Session expired
   ```

---

### مشکل: Webhook تلگرام توسط افراد مخرب استفاده می‌شود

**علت:** Secret Token تنظیم نشده است.

#### راه‌حل:

1. **تنظیم Secret:**
   ```
   TELEGRAM_WEBHOOK_SECRET_NAME=telegram-secret
   ```

2. **ثبت مجدد Webhook:**
   - با secret token جدید
   - در پنل مدیریت

3. **بررسی لاگ:**
   ```
   Webhook secret mismatch - rejected
   Valid webhook received from Telegram
   ```
